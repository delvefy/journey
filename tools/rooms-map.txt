JOURNEY — THE RIDDLE-HOARD — ROOM TRACKER
=========================================

HOW TO WRITE THE NEXT ROOM
  - Write rooms ONE AT A TIME, never in batches: write the room, save the HTML,
    update the LAST ROOM line below, and ONLY THEN start the next room. Saving each
    room before beginning the next is what makes the work safe to interrupt.
  - "Write the next N rooms" means repeat that one-room loop N times (write, save,
    update tracker, proceed) — NOT write N at once, and NOT stop after one. "Write
    the next room" is just N = 1.
  - The next room is the unwritten coordinate CLOSEST to the origin (0,0):
    smallest straight-line distance; ties broken clockwise from north
    (N, NE, E, SE, S, SW, W, NW).
  - Each room IS a single-word/number answer; its four boxes hold riddles whose
    answers are the four NEIGHBOUR names. Read existing neighbours first and match
    their names exactly (the 2D-crossword rule). Full rules: see write.txt.
  - Difficulty is BANDED by distance d = sqrt(x*x + y*y) and enforced — write to
    the band, match a written sibling, never let it drift (write.txt section 4).
  - Duplicate names ARE allowed (finite per-band vocabulary) but policed by hoard.py:
    no twin (same name as any of the 8 neighbours), no clone (same name + same four
    neighbours), same-name rooms >= D_MIN apart. render refuses, verify flags. See
    write.txt section 5; the index lives in tools/names.json (rebuild: hoard.py reindex).
  - Save it as rooms/<x>/<y>.html, then update the LAST ROOM line below.

NEXT ROOM
  The blob is grown closest-first from 0:0; LAST ROOM above pins the frontier. The next
  unwritten coordinate is -16:-10 (d=18.868, Approach), then the rest of the d~=18.9-19 ring
  outward. This list goes stale fast — run `hoard.py next` for the live order and
  `hoard.py plan` for the per-wall briefing before writing anything.

  HELPER (added this session): tools/pick.py X Y word1 word2 ... vets candidate NAME-IT words
  against names.json AND the lexicon at once — prints SAFE/BLOCKED (with nearest same-name
  room/commit + distance) and (lex)/(NOT-IN-LEX). It catches commit-vs-commit clashes that
  `plan`'s avoid-list (written-rooms only) misses, so render refuses far less often.

  The outer Approach rings are saturated: each new NAME-IT cell usually has ONE in-lex word
  free, often none. When none, bless a genuinely-plain child word with `render --allow WORD`
  (this session blessed e.g. squash, mash, slip, glide, shake, flap, foot, neck, tooth, rib,
  belly, throat, lip, palm, shin, raccoon, chipmunk, cricket, teapot, sink, piano, flute,
  violin, triangle, chirp, zoom). Never reach for a hard word; reuse or bless plain ones.

  Keep every Approach name a plain everyday word a child would say unprompted. The blob
  was once wiped and re-grown because its outer rings had drifted into verse/music, trade,
  naturalist and archaic words (octave, sonnet, zephyr, bracken, silt, murk, ...). Don't
  let it happen again — see write.txt section 4, anti-drift rule iv.

MIN-GAP POLICY (D_MIN = 15, ALWAYS respected — changed)
  render NEVER writes a sub-D_MIN duplicate, and `--d-min` may only TIGHTEN the gap, never
  relax it below 15. The blind spot is CLOSED: names.json carries a `commits` map and
  render's `commit_violations` refuses a free NAME-IT/commit that would sit within D_MIN of
  a same-name written-or-committed cell. A crossword-FORCED name is skipped by that gate
  (no free choice) but still checked as the room's own name — so when you reach an inherited
  cell whose forced name lands within D_MIN of a twin, render REFUSES it; fix by re-rendering
  the upstream committer with a FRESHER answer (bless a plain word: `words add WORD`).
  When a quadrant feels "used up", BLESS a fresh plain word rather than reuse a near one —
  an unused word clears D_MIN for free. The lexicon is a difficulty gate, not a supply cap.

KNOWN ACCEPTED DUPLICATES (inherited, do not "fix")
  Several same-name pairs predate the always-respected policy and remain (their names are
  crossword-locked, so clearing them would break the grid): 'frog' -6:-3 ~ -2:-7 (5.66),
  plus 'worry','whisper','snow','cry','hat','shine','cup' (4.1-13.9 apart). `reindex` lists

  and the dist-1.0 'temper'/'grasshopper' twins WERE fixed -> elbow, fib, hush, ankle.)

THE FOUR CORNERS  (planted AHEAD of the grid — see write.txt section 12)
  The world is bounded -150..+150 on both axes, so it has four true corners, the
  hardest rooms (d = 212.13). They were written out of order as endgame flags and
  are NOT part of the contiguous blob — they do NOT move the LAST ROOM frontier
  above, and the next normal room is unaffected. Their four names spell, in the
  one ordering that is a sentence:   WORDS  OPEN  ALL  WALLS.
    NE  150:150    Words   inward riddles → S hour,  W rune
    SE  150:-150   Walls   inward riddles → N gate,  W nail
    SW  -150:-150  All     inward riddles → N loam,  E ore
    NW  -150:150   Open    inward riddles → S mist,  E hush
  Each corner's other two walls are the off-grid rim of the world — sealed, no
  riddle. They are not reachable by normal play until the whole grid is finished.
