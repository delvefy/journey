VLAD'S JOURNEY — PROJECT CHEATSHEET (for AI assistants)
=======================================================

WHAT THIS IS
------------
"Vlad's Journey", published as a fully static site (GitHub Pages, custom
domain in CNAME: journey.victorblackauthor.com). No build step, no framework,
no server code. Plain HTML + CSS + vanilla JS.

It was originally a random-topic encyclopedia; it has been REPURPOSED into a
single structured COURSE in penetration testing, running beginner ->
intermediate -> advanced, tailored for Vlad (QA engineer, works on a MacBook).
Each "article" is now a LESSON. The front page shows the course description, a
search box, and the curriculum in lesson order.

This file (meta.txt) describes the SITE PLUMBING. The task of WRITING the next
lesson is governed by a separate file, produce.txt — read it for the learner
profile, curriculum arc, lesson structure, and the safety rules. The two files
are companions: produce.txt for content, meta.txt for layout/styling/JSON.

STRUCTURE
---------
index.html              Front page: description, search, curriculum list.
                        Fetches db/articles.json client-side and renders it,
                        sorted by `lesson` ascending (course order).
style.css               Shared stylesheet for ALL pages (front page + lessons).
                        Includes lesson apparatus: code/terminal blocks and
                        .callout panels (see "Lessons" section in the CSS).
db/articles.json        The "database": one JSON array indexing every lesson.
                        Used for search (title/summary/tags) and lesson order.
articles/<slug>.html    One static, self-contained page per lesson.
                        Naming: lesson-NN-<kebab-topic>.html.
produce.txt             How to write the NEXT lesson (the recurring task).
meta.txt                This file (site plumbing).
CNAME                   GitHub Pages domain — do not touch.

THE DATABASE: db/articles.json
------------------------------
A JSON array. One object per article:

  {
    "slug": "lesson-01-introduction-to-penetration-testing",
                                        // kebab-case; must match the filename
                                        // articles/<slug>.html
    "title": "Lesson 1 — Introduction to Penetration Testing",
    "summary": "One or two sentences shown in lists and used by search.",
    "tags": ["beginner", "foundations"],// lowercase; FIRST tag = the level
    "date": "2026-06-13",               // ISO YYYY-MM-DD; the day it was written
    "lesson": 1,                        // integer; the front page sorts on this
    "level": "beginner"                 // beginner | intermediate | advanced
  }

`lesson` and `level` are the course fields; the front page orders by `lesson`
ascending and shows "Lesson N · level" where the date used to be.
More .json files may be added to db/ later if a feature needs them.

HOW TO ADD A LESSON (the routine task)
--------------------------------------
This is now governed by produce.txt — read it. In short:
1. Read db/articles.json; find the highest `lesson` number (the last lesson).
2. Read that lesson's HTML (and skim the one before) for continuity.
3. Write articles/lesson-NN-<kebab-topic>.html using the skeleton and lesson
   structure in produce.txt (theory + hands-on lab + takeaways + self-check).
4. Append an entry to db/articles.json (slug = filename, plus lesson + level).
The front page picks it up automatically and slots it into course order.

A real specimen: articles/lesson-01-introduction-to-penetration-testing.html

The lesson HTML skeleton, content structure, learner profile, curriculum arc,
writing voice, and the (non-negotiable) safety/legal rules all live in
produce.txt. The plumbing and design language below still apply to every page.

DESIGN LANGUAGE (style.css)
---------------------------
Theme: "a leather-bound encyclopedia read by lamplight" — dark, traditional,
amber-gilded. All tokens are CSS variables in :root of style.css:
  --paper   #1c1610  page background (deep umber)
  --ink     #e7dcc3  body text (parchment)
  --amber   #e0a832  accent: links, tags, drop caps, small-caps headings
  --rule    #463a27  hairline rules
Fonts (Google Fonts): "IM Fell English" (display), "IM Fell English SC"
(small-caps labels), "EB Garamond" (body). Motifs: double rules, the
fleuron ❦, small caps, drop cap on the lead, ruled section headings.
New UI must reuse these variables and motifs — never introduce off-theme
colors, sans-serif fonts, or "modern app" styling (cards with big radii,
gradients, shadows, etc.).

RULES / GOTCHAS
---------------
- Keep everything static: no build tools, no npm, no frameworks.
- Lesson pages live one level deep, so they reference ../style.css and
  ../index.html.
- The slug in db/articles.json MUST equal the filename (front page builds
  links as articles/<slug>.html).
- The front page orders by the `lesson` integer ascending; any entry without
  a `lesson` field sinks to the bottom. Keep lesson numbers contiguous.
- Search is client-side substring matching over title + summary + tags;
  every JSON entry should have a meaningful summary so search works well.
- Inside <pre>/<code>, use plain ASCII (not &mdash;/&rsquo;) so commands
  copy-paste correctly. Typographic entities are for prose only.
- When changing shared styling, check both index.html and a lesson page.
