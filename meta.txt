VLAD'S JOURNEY — PROJECT CHEATSHEET (for AI assistants)
=======================================================

WHAT THIS IS
------------
A personal wiki / encyclopedia called "Vlad's Journey", published as a fully
static site (GitHub Pages, custom domain in CNAME: journey.victorblackauthor.com).
No build step, no framework, no server code. Plain HTML + CSS + vanilla JS.

Vlad adds articles from time to time. Articles look like traditional
encyclopedia entries (Wikipedia-like) and carry tags. The front page shows a
short site description, a search box, and the most recently added articles.

STRUCTURE
---------
index.html              Front page: description, search, recent articles.
                        Fetches db/articles.json client-side and renders it.
style.css               Shared stylesheet for ALL pages (front page + articles).
db/articles.json        The "database": one JSON array indexing every article.
                        Used for search (title/summary/tags) and recency sort.
articles/<slug>.html    One static, self-contained page per article.
meta.txt                This file.
CNAME                   GitHub Pages domain — do not touch.

THE DATABASE: db/articles.json
------------------------------
A JSON array. One object per article:

  {
    "slug": "about-this-wiki",          // kebab-case; must match the filename
                                        // articles/<slug>.html
    "title": "About this wiki",
    "summary": "One or two sentences shown in lists and used by search.",
    "tags": ["meta"],                   // lowercase, short, reusable
    "date": "2026-06-11"                // ISO YYYY-MM-DD; drives "recently added"
  }

More .json files may be added to db/ later if a feature needs them.

HOW TO ADD AN ARTICLE (the routine task)
----------------------------------------
1. Pick a kebab-case slug from the title (e.g. "the-silk-road").
2. Create articles/<slug>.html from the skeleton below, following the
   ARTICLE STRUCTURE rules strictly.
3. Append an entry to db/articles.json (slug, title, summary, tags, date = today).
That's it — the front page picks it up automatically. Nothing else to update.

A real specimen following the house style: articles/about-this-wiki.html

ARTICLE STRUCTURE (strict — every article, no exceptions)
---------------------------------------------------------
An article takes one of two shapes, decided by how much reliable material
the subject offers:

1. OVERVIEW — mandatory, 500–1000 words.
   The whole subject in miniature: the lead paragraph (class="lead")
   defining it, then a few short <h2> sections covering the essentials.
   A reader who stops at the end of the overview must still walk away
   with the complete picture. The infobox, if any, belongs here.

2. DEEPER DELVE — only when information is abundant, 5000–10000 words.
   Follows the overview, separated by an <hr> and opened with the
   heading <h2>A deeper delve</h2>. Its internal sections use <h3>
   (and <h4> below that if needed). This is where the full history,
   mechanics, figures, controversies and consequences live, at
   encyclopedic depth.

If the subject cannot honestly sustain 5000 words, stop after the
overview — never pad. If it can, the delve is obligatory — never
compress a rich subject into the overview alone. References, when
present, come last of all (after the delve if there is one).

HOUSE STYLE (writing)
---------------------
- Encyclopedia voice: third person, measured, slightly old-fashioned; wit is
  welcome, hype is not.
- Follow ARTICLE STRUCTURE above strictly: overview always (500-1000 words);
  deeper delve (5000-10000 words) only when the material is abundant.
- Open with a lead paragraph (class="lead") that defines the subject.
- Divide longer entries into <h2> sections; use the infobox for quick facts.
- Tags: lowercase, singular where sensible, reuse existing tags before
  inventing new ones (check db/articles.json for the current vocabulary).
- Typographic niceties: &mdash; for dashes, &rsquo; for apostrophes,
  &ldquo;&rdquo; for quotes.

DESIGN LANGUAGE (style.css)
---------------------------
Theme: "a leather-bound encyclopedia read by lamplight" — dark, traditional,
amber-gilded. All tokens are CSS variables in :root of style.css:
  --paper   #1c1610  page background (deep umber)
  --ink     #e7dcc3  body text (parchment)
  --amber   #e0a832  accent: links, tags, drop caps, small-caps headings
  --rule    #463a27  hairline rules
Fonts (Google Fonts): "IM Fell English" (display), "IM Fell English SC"
(small-caps labels), "EB Garamond" (body). Motifs: double rules, the
fleuron ❦, small caps, drop cap on the lead, ruled section headings.
New UI must reuse these variables and motifs — never introduce off-theme
colors, sans-serif fonts, or "modern app" styling (cards with big radii,
gradients, shadows, etc.).

RULES / GOTCHAS
---------------
- Keep everything static: no build tools, no npm, no frameworks.
- Article pages live one level deep, so they reference ../style.css and
  ../index.html.
- The slug in db/articles.json MUST equal the filename (front page builds
  links as articles/<slug>.html).
- Dates are ISO in the JSON and in <time datetime>; rendered dates are
  long-form British style ("11 June 2026").
- Search is client-side substring matching over title + summary + tags;
  every JSON entry should have a meaningful summary so search works well.
- When changing shared styling, check both index.html and an article page.
