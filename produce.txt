PRODUCE-NEXT-ARTICLE — INSTRUCTIONS FOR CLAUDE
================================================

WHEN THE USER SAYS "produce next N articles":
  Loop the PROCEDURE below N times. Each iteration is fully self-contained —
  if something fails mid-batch, every article completed so far is still on disk
  and state.json points at the next one to write.

PROJECT LAYOUT
--------------
  /index.html            ranked list (rendered from counter.json by JS)
  /style.css             shared styles, mobile-friendly
  /counter.json          [{ "name": "...", "slug": "...", "count": N, "order": K }, ...]
                         "order" is the chronological position on the road (Jesus = 1,
                         then 2, 3, ... in the sequence articles are written). It never
                         changes once assigned. The index page can sort by count or by order.
  /state.json            { "next_name": "...", "next_slug": "...", "seeded_from": "..." }
  /articles/<slug>.html  one file per person
  /produce.txt           this file

SLUG RULES
----------
  lowercase, ASCII only, spaces -> hyphens, strip punctuation.
  Examples:
    "Jesus Christ"          -> "jesus-christ"
    "Joseph of Arimathea"   -> "joseph-of-arimathea"
    "Eleanor of Aquitaine"  -> "eleanor-of-aquitaine"
    "Charlemagne"           -> "charlemagne"

INITIAL SEEDING
---------------
  If state.json.next_slug is null, the user must pick the first person.
  Once picked, set state.json.next_name + next_slug and run the procedure.

PROCEDURE (one article)
-----------------------
1. Read state.json. Let TARGET = { next_name, next_slug }.
   If TARGET.next_slug is null, stop and ask the user for a starting person.

2. Read counter.json into MEM.

3. Write articles/<TARGET.next_slug>.html using the ARTICLE TEMPLATE below.
   The body must be 800-1200 words covering the most important deeds of
   TARGET.next_name's life: origins, formative events, principal achievements,
   conflicts and turning points, legacy. Plain prose, paragraphs, no headings
   inside the article body. Do NOT invent facts — if uncertain, omit.
   Leave the "next link" pointing to a placeholder you will fill in step 7.

4. Ensure TARGET is in counter.json:
   - If MEM already has an entry with slug == TARGET.next_slug, leave count and order alone
     (this should not normally happen, since TARGET was a "new" pick last round).
   - Otherwise append { name: TARGET.next_name, slug: TARGET.next_slug, count: 1,
     order: 1 + max(existing entries' order, or 0 if MEM was empty) }.

5. Build a short ranked candidate list of real historical persons closely
   connected to TARGET (family, mentor, pupil, ally, rival, contemporary,
   patron, successor, biographer, etc.). Rank using this composite:

       narrative density  ×  symmetric importance  ×  onward branching

   - narrative density: how much of TARGET's life cannot be told without
     this person.
   - symmetric importance: would TARGET be a top-3 connection in THIS
     person's article too? Symmetric edges beat asymmetric ones.
   - onward branching: does this person open onto a rich further graph,
     or are they a near-dead-end?

   Hard gate: historical solidity. Drop any candidate whose record is
   primarily legendary or whose existence is seriously disputed —
   Arthurian / Grail / hagiographic figures do not qualify.

   Keep the shortlist mental — do not write it to disk, the article, or
   state.json. Only the final pick is visible anywhere.

6. Walk the ranked list starting at POSITION 1. For each position
   considered, in order 1, 2, 3, ...:
   - If that candidate's slug is already in MEM, increment that entry's
     count by 1 and move to the next position.
   - The first considered candidate that is NOT already in MEM becomes
     CANDIDATE.
   If the shortlist runs out before a new pick is found, extend it; do not
   lower the gate.

7. Finalize the article we wrote in step 3: replace the next-link placeholder
   with a real link:
     <a href="<CANDIDATE.slug>.html"><CANDIDATE.name></a>
   The target file does not need to exist yet — the link is forward-looking.

8. Write counter.json (pretty-printed, 2-space indent, trailing newline).

9. Write state.json with:
     next_name   = CANDIDATE.name
     next_slug   = CANDIDATE.slug
     seeded_from = TARGET.next_slug

10. (No need to touch index.html — it reads counter.json at load time.)

ARTICLE TEMPLATE (articles/<slug>.html)
---------------------------------------
<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title><PERSON NAME></title>
<link rel="stylesheet" href="../style.css">
</head>
<body>
<main class="wrap">
  <header class="site"><a href="../index.html">&larr; All the roads lead to:</a></header>
  <article>
    <h1><PERSON NAME></h1>
    <p class="byline"><LIFESPAN OR ONE-LINE EPITHET></p>

    <p>...paragraph 1...</p>
    <p>...paragraph 2...</p>
    ...
    <p>...final paragraph...</p>

    <p class="next-link">The road continues to <a href="<CANDIDATE-SLUG>.html"><CANDIDATE NAME></a>.</p>
  </article>
</main>
</body>
</html>

NOTES
-----
- Articles link sideways within the articles/ folder, so use relative hrefs
  like "joseph-of-arimathea.html" (no "articles/" prefix).
- Stylesheet is at "../style.css" because articles live one level deep.
- The byline line is one short italic line: dates if known, otherwise a brief
  epithet ("Roman emperor", "Florentine painter").
- Do not put any headings inside the article body — only the H1 title.
- Keep word count between 800 and 1200. Count before committing.
- Never silently overwrite an existing article file. If <slug>.html already
  exists at step 3, something is wrong — stop and report to the user.
